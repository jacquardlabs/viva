| # | Lane | Failure mode | Detection hint |
|---|------|--------------|----------------|
| 1 | technical | `start` (parse+launch) and `rearm` (re-parse+POST) are atomic, closing the seam every producer writes into. `SKILL.md:74–90` splits round 1 into parse → producer → launch, and `:271–276` pins round 2+ producers between the re-parse and the POST. The learned-preference producer **auto-engages** at round 1 (`:301`, `:370`) whenever a standing preference exists, so this silently drops a default-on feature — and disables CLAUDE.md's documented preferred extension point. | `grep -n 'annotate\|producer' scripts/loop.py` returns nothing, or `loop.py start` has no `--parse-only`/`arm` split. Functional check: seed `.viva/preferences.json` with a standing preference, run the loop, confirm no `kind:"preference"` annotation reaches `review-input-r1.json`. |
| 2 | technical | The `/complete` all-approved guard keys on `sections` in `_input_data`, and `parse_diff.py` emits `sections` — so diff sessions are review-shaped and the guard fires on them. `viva-diff/SKILL.md:88–97` POSTs `/complete` on an empty re-diff, and `:110–113` says that path is reached *because hunks were reverted, not approved* — the latest verdicts hold `changes`. A legitimate finish 4xxes, the server leaks, the tab strands. | `git diff` the `/complete` handler for a `mode`/diff exemption. Functional check: run `/viva-diff`, request changes on a hunk, revert it so the re-diff is empty, confirm `/complete` returns 200 and the process exits. |
| 3 | product | `submitted_early` rounds have a refusal but no routing rule. `wait` prints the flag, but nothing classifies the round, so the agent discovers the dead zone only by guessing `finish` and being refused — and an agent that guesses `rearm` instead re-presents forever without telling the user. The defect the story exists to remove survives as a slower version of itself. | Read the slim SKILL.md's verdict table for a third row covering the paused-reviewer case. Functional check: hit **skip rest & submit** mid-review and confirm the agent reports the pending count to the user rather than silently re-arming. |
| 4 | product | After **skip rest & submit** (`DESIGN.md:267–288` makes it a first-class control), `finish` refuses, `/complete` never fires, and the reviewer's tab holds `#processing-view`'s "the agent is revising" card indefinitely while the agent asks a question in a terminal the reviewer isn't watching. The doc's "moves no pixels" claim doesn't hold on this path. | Check whether the design names what the tab shows during a refusal. Functional check: skip mid-review and watch the browser — a permanently pulsing processing card is the failure. |
| 5 | technical | Fork 2 relocates ~140 lines to `references/`, which must resolve from the installed plugin cache — a mechanism the out-of-scope `viva-dir-resolve` story owns, with no dependency edge recorded between them. If resolution fails, annotations, producers, confidence, open notes, and preferences all degrade silently to undocumented. | `gate-ledger epic-get --slug reliability` shows no `deps` edge from this story to `viva-dir-resolve`. Functional check: run the skill from a clean plugin-cache install and confirm every relocated reference loads. |
| 6 | product | The auto-approve hatch at `SKILL.md:134` is deleted as a side effect of the rewrite, with no acceptance criterion asserting its absence and its replacement prose deferred to `skill-prose-fixes`. Between the two stories, viva has no documented rule for "a doc too short to review" — against PRODUCT.md's hard line that nothing is auto-accepted. | `grep -n 'auto-approved\|too short to review' .claude/skills/viva/SKILL.md` returning nothing *and* no replacement rule present is the failure, not the fix. |
| 7 | technical | The server-side guard's verdict source is unspecified — last-submit in-memory state vs. re-reading `_output_path`. The choice decides whether `/complete` before any submit reads as "no verdicts yet" or "not all approved", which are two different agent recoveries, and the design specifies one 4xx message for both. | Read the `/complete` handler for where verdicts come from. Functional check: POST `/complete` to a freshly launched review session before any submit and read the error message. |
